# 已知失败清单（测试隔离 / test quarantine）
#
# 用途：`python -m pytest tests` 在当前仓库状态下有 40 个**既有**失败，
# 与本文件无关的改动无关。CI 通过 `--deselect` 跳过这些用例，
# 从而做到「新引入的失败必红、历史遗留失败不阻塞」。
#
# 背景：这些用例长期无人执行（历史上只单独跑个别文件），
# 直到 2026-09 把全量测试接入 CI 才暴露出来。
#
# 主要类别：
#   A. SQLite 环境差异（占比最大）：测试自建 `create_engine("sqlite+pysqlite://")`
#      并只 create_all 部分表，而业务代码写向另一处引擎/未建表 →
#      `sqlite3.OperationalError: no such table: audit_logs / dimension_item /
#      lightning_current_backfill_task`；以及 `can't compare offset-naive and
#      offset-aware datetimes`（SQLite 不保留时区）。这些用例在 PostgreSQL 上应可通过。
#   B. 真实契约漂移（**应尽快修，不要长期隔离**）：
#      - tests/test_task_name_registry.py、test_task_monitor_service.py::
#        TestTaskNameLabelMappingSync —— 前端 web/src/lib/celery-task-display.ts
#        的任务名映射与后端 celery 注册表不一致（dead/missing key）。
#      - tests/test_celery_long_task_config.py —— broker visibility_timeout
#        期望值与实际不一致（断言 86400 != 21600）。
#   C. 零散用例问题：数值断言、fixture 缺字段（如 SimpleNamespace 无 tower）、
#      NameError 等，需逐个诊断。
#
# 处理方式：修好一个就从本文件删掉对应行（CI 会立刻开始守护它）。
#
# 格式（每行一个 pytest node id，相对 api/ 目录）：
