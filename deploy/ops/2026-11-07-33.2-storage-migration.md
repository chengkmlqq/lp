# 33.2 存储架构迁移记录（2026-11-07）

## 背景

- 系统盘 `/dev/vda1` 29G 已用 85%，只剩 4.6G；业务数据 2.8G 压在系统盘
- 数据盘 `/dev/vdb1` 10G 仅用于 `/var/lib/docker/volumes`，只用了 700M
- 模型文件原存阿里云 OSS，AccessKey 被禁用（`UserDisable`），读写全部失败，
  平台连已有模型都下载不了，所有仿真无法执行

## 目标架构

```
/dev/vdb1 ──► /data                         fstab 按 UUID 挂载，nofail
               ├── docker-volumes  ──bind──► /var/lib/docker/volumes
               └── lp/app          ──bind──► 各容器 /app/data
                     ├── vfs/atp-assets/<电压>/<塔型>/<场景>/<避雷器>/
                     ├── wine/           ATP 引擎与运行目录
                     └── test/           测试脚本与几何数据
```

对象存储由阿里云 OSS 改为**平台内置 VFS 驱动**（本地磁盘），不引入 MinIO。

## 执行步骤

```bash
# 1. 停 docker（具名卷会被卸载）
systemctl stop docker.socket; systemctl stop docker

# 2. 数据盘改挂 /data，卷数据归位后 bind 回原路径
umount /var/lib/docker/volumes
mkdir -p /data && mount /dev/vdb1 /data
mkdir -p /data/docker-volumes
mv /data/* /data/docker-volumes/          # 注意排除 docker-volumes 自身
mount --bind /data/docker-volumes /var/lib/docker/volumes

# 3. fstab（/etc/fstab）
# UUID=4941a3df-cfab-433a-9275-19f70b36f6b4 /data ext4 defaults,nofail,x-systemd.device-timeout=30s 0 2
# /data/docker-volumes /var/lib/docker/volumes none bind,nofail,x-systemd.requires-mounts-for=/data 0 0
systemctl daemon-reload && findmnt --verify --verbose

# 4. 业务数据迁到数据盘
mkdir -p /data/lp && cp -a /opt/lp/data/app /data/lp/app
mv /opt/lp/data/app /opt/lp/data/app.old-<日期>     # 校验文件数一致后再删
ln -s /data/lp/app /opt/lp/data/app                 # 保留旧路径引用

# 5. compose 挂载改为宿主机绝对路径
#    - /data/lp/app:/app/data       (api / celery-worker / beat / wine-worker)
#    - /data/lp/app:/data/app       (proxy)
cd /opt/lp && docker compose up -d

# 6. 存储后端切本地 VFS（写库，非改代码）
#    file_storage_backends: files.vfs.default → status=enabled, is_default=1
#    file_storage_backends: files.s3.default  → status=disabled
#    file_storage_mounts:   main → backend=files.vfs.default, root_path=/
```

VFS 的 `config.root_dir` 保持 `/app/data/vfs`，即实际落盘 `/data/lp/app/vfs`。

## 验证

| 项 | 结果 |
|---|---|
| VFS 驱动读写 | 写/读/列目录/删除全部正常，落地 `/data/lp/app/vfs` |
| 资产解析抽样 | 110/220/35/500/1000 六例 `work.atp` 均可读出（17~45 KB） |
| 冒烟算例 | 110 guxing fanji noM → 反击耐雷 65.77 kA，绕击跳闸率 0.1136，与本次改造前一致 |
| 老模型入库 | 702 个模型 / 8804 文件 / 130 MB，全部 `is_published=1`、`is_active=1` |
| 其他栈 | kb-pg、kb-neo4j、multica-postgres 均正常启动，数据无损 |

容量：`/data` 3.7G/9.8G（剩 5.7G），`/` 22G/29G（剩 7.7G）。单次仿真运行目录约 4 MB。

## 回滚

```bash
systemctl stop docker
umount /var/lib/docker/volumes
umount /data
mount /dev/vdb1 /var/lib/docker/volumes      # 恢复原挂载点
# fstab 还原 /root/fstab.bak-20261107
# compose 还原 /root/compose.bak-20261107.yml
systemctl start docker
```

## 注意

1. **跨主机 worker 失效**：模型在本机磁盘，只有挂载同一 `/data/lp/app` 的容器可读。
   多 worker 只能在同一台机器加副本，且同塔型并发必须为 1（引擎目录按塔型共享，
   `GEOMETRY_LOCK` 是线程锁，`--concurrency>1` 会算串）。
2. `docker.io` 拉取 minio 镜像被拒（`denied`），自建 S3 方案不可行；平台 VFS 驱动已够用。
3. 故障分析 / 雷电模块仍走 `app/services/minio_storage.py` 直连 OSS，未随本次改造迁移，
   AK 失效后这两个模块本就不可用，需要本地化时再单独处理。
