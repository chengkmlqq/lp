# 维度管理页面改造方案（对齐系统参数管理）

> 目标：将维度管理页面改造为"维度类型管理 + 维度值管理"双栏布局，左侧维度类型树、右侧维度值列表，后台处理逻辑与前台交互完全参照系统参数管理页面（`admin/system-params`）。

---

## 1. 背景与目标

### 1.1 现状问题（维度管理）

- **单表自由字符串**：所有维度（电压等级/塔型/场景/避雷器组合…）存在 `dimension_item` 一张表，`dimension_type` 是**用户自由输入的字符串**（表单 Input+Select tags），无枚举、无字典、无独立维护入口。
- **隐患**：类型拼写不一致会产生"同名不同值"脏数据（如 `voltage_level` vs `VoltageLevel`）；删除/重命名类型无约束；类型无法统一排序、启用/停用。
- **单栏布局**：页面只有一个维度值表格，类型只能作为筛选下拉（从已加载数据动态提取），没有独立的类型管理界面。

### 1.2 改造目标

参照系统参数管理页面（`web/src/app/admin/system-params/page.tsx` + `system_param_categories` 后台）：

1. **新增维度类型实体**（`dimension_type` 表），维度值通过外键关联类型；
2. **左右布局**：左侧维度类型树（可搜索、可新建/重命名/删除、可拖拽宽度），右侧维度值列表（按选中类型过滤）；
3. 后台处理逻辑（类型树 CRUD + 值列表 CRUD + 删除保护 + 排序）对齐 `system_param_categories` / `system_params`；
4. 前台页面布局、交互（Tree、可拖拽分割条、卡片/表格视图切换）对齐系统参数页。

---

## 2. 现状对比（维度 vs 系统参数）

| 维度 | 系统参数（参照物） |
|---|---|
| 单表 `dimension_item`，`dimension_type` 自由字符串 | 双表：`system_param_categories`（分类树）+ `system_params`（参数，`category_id` FK） |
| 无类型管理界面 | 分类树 CRUD（新建分类/重命名/删除） |
| 类型下拉从已加载数据动态提取 | 分类树接口 `/admin/system-param-categories/tree` |
| `dimension_item.parent_id` 自引用（值可树形） | 分类树自引用（`parent_id` + `children` selectinload）；参数表无树 |
| 列表筛选：keyword/type/enabled | 列表筛选：keyword/status/category_id |
| 删除：有子节点拒绝删除 | 删除：有参数引用拒绝删除 |

**核心差异**：系统参数把"分类"独立成表 + 参数外键关联；维度把"类型"内联为字符串。改造 = 把类型独立成表 + 维度值外键关联。

## 3. 总体设计

### 3.1 数据模型（新增 1 表，改造 1 表）

```sql
-- ① 新增 dimension_type（维度类型表，对齐 system_param_categories 风格，uuid 主键）
CREATE TABLE dimension_type (
    id          VARCHAR(32) PRIMARY KEY,                    -- uuid4 hex
    code        VARCHAR(64)  NOT NULL UNIQUE,               -- 类型编码（如 voltage_level）
    name        VARCHAR(128) NOT NULL,                      -- 类型名称（如 电压等级）
    parent_id   VARCHAR(32) REFERENCES dimension_type(id) ON DELETE SET NULL,  -- 类型树（可多级）
    description TEXT,
    is_enabled  BOOLEAN DEFAULT TRUE,
    sort_order  INTEGER DEFAULT 0,
    create_date TIMESTAMPTZ DEFAULT now(),
    create_user VARCHAR(64),
    update_date TIMESTAMPTZ DEFAULT now(),
    update_user VARCHAR(64)
);
CREATE INDEX idx_dimension_type_parent  ON dimension_type (parent_id);
CREATE INDEX idx_dimension_type_enabled ON dimension_type (is_enabled);
CREATE INDEX idx_dimension_type_sort    ON dimension_type (sort_order);

-- ② 改造 dimension_item（维度值表加类型外键）
ALTER TABLE dimension_item ADD COLUMN type_id VARCHAR(32)
    REFERENCES dimension_type(id) ON DELETE RESTRICT;        -- 有值引用禁止删类型
CREATE INDEX idx_dimension_item_type_id ON dimension_item (type_id);
```

**兼容策略（推荐）**：`dimension_item.dimension_type` 字符串列**保留过渡期**（新代码双写 `type_id` + `dimension_type`；读取以 `type_id` JOIN 为准），确认稳定后二期迁移删除。过渡期好处：回滚无风险、旧接口兼容。

### 3.2 数据迁移

```
1. 备份数据库
2. 建 dimension_type 表
3. INSERT INTO dimension_type (id, code, name, ...)
   SELECT DISTINCT ON (dimension_type) md5(dimension_type), dimension_type, dimension_type
   FROM dimension_item WHERE dimension_type IS NOT NULL;      -- 现有类型去重落表
4. UPDATE dimension_item SET type_id = (SELECT id FROM dimension_type WHERE code = dimension_item.dimension_type);
5. 校验：UPDATE 后 type_id IS NULL 的记录数 = 0
6. 业务切换（代码走 type_id）→ 验证 → 二期删除 dimension_type 列
```

### 3.3 API 设计（新增 4 个类型端点 + 改造值端点）

| 方法 | 路径 | 功能 | 对齐参考 |
|---|---|---|---|
| GET | `/api/v1/dimensions/types/tree` | 类型树（selectinload children + sort_order） | `/admin/system-param-categories/tree` |
| POST | `/api/v1/dimensions/types` | 创建类型（code 查重 409） | `/admin/system-param-categories` |
| PATCH | `/api/v1/dimensions/types/{id}` | 更新类型（name/parent/sort/启用） | `/admin/system-param-categories/{id}` |
| DELETE | `/api/v1/dimensions/types/{id}` | 删除类型（**有维度值引用 → 409**） | `/admin/system-param-categories/{id}` |
| GET | `/api/v1/dimensions?type_id=&keyword=&status=` | 维度值列表（**type_id 过滤**） | `/admin/system-params?category_id=` |
| POST | `/api/v1/dimensions` | 创建维度值（type_id 必填 + `(type_id, code)` 查重） | `/admin/system-params` |
| PATCH | `/api/v1/dimensions/{id}` | 更新维度值 | `/admin/system-params/{id}` |
| DELETE | `/api/v1/dimensions/{id}` | 删除维度值（有子节点拒绝，保留现有） | 现有逻辑 |
| GET | `/api/v1/dimensions/tree?type_id=` | 维度值树（保留，type_id 过滤） | 现有逻辑扩展 |

权限：全部复用 `dimension.read` / `dimension.manage`（类型与值同权限，对齐系统参数用 `system_param.read/manage` 管两类）。

交互细节（照抄 system-params 模式）：
- `leftPanelWidth` state + `handleResizeStart`（`e.clientX - rect.left`，clamp 180/600）
- `selectedTypeId` + 树 `onSelect` → 刷新右侧列表（type_id 入参）
- 类型树操作：行内 Dropdown（重命名/删除），删除有值引用时后端 409 → 前端 toast
- WS 订阅 `admin.dimension-types`（新）+ 现有 `admin.dimension-items`，变更自动刷新

## 5. 实施步骤

**Phase 1 — 后端类型实体**
1. `dimension_type` 模型 + migration 011（建表 + 数据迁移 + type_id 回填）
2. `dimension_type_service.py` + API 端点（tree/CRUD/删除保护）
3. 单测：类型 CRUD、删除保护（有值 409）、code 查重

**Phase 2 — 维度值接入类型**

5. `(type_id, code)` 查重替换原 `(dimension_type, code)`；老接口兼容（dimension_type 参数 → 解析 type_id）

**Phase 3 — 前端改造**
6. `dimensions/page.tsx` 重写为左右布局（照抄 system-params 结构）
7. 类型树 CRUD 交互 + 右侧值表格 + WS 订阅

**Phase 4 — 验证与收尾**
8. 全量验证（§7）+ 回归（现有维度数据完整、菜单引用不回归）

## 6. 验收标准

- [ ] `dimension_type` 表可 CRUD，树接口返回完整层级（sort_order 排序）
- [ ] 现有维度数据迁移完整：`type_id` 回填率 100%，无 NULL
- [ ] 创建/编辑维度值时类型**必选**（从类型树/下拉，不可自由输入）
- [ ] 左侧选中类型 → 右侧列表按 `type_id` 过滤正确；"全部维度"显示全部
- [ ] 删除被引用的类型 → 409 + 前端提示；无引用类型可删除
- [ ] `(type_id, code)` 重复 → 409
- [ ] 类型重命名/停用后，右侧维度值随之更新（JOIN 展示类型名）
- [ ] 前端布局对齐系统参数：可拖拽分割条、搜索类型树、卡片/表格视图切换、移动端降级
- [ ] 既有测试全绿 + 新增 2 个测试文件通过
- [ ] WS 自动刷新（类型/值变更后页面无需手动刷新）

## 7. 风险与兼容

| 风险 | 缓解 |
|---|---|
| 已有维度数据依赖字符串 `dimension_type` | 迁移去重落表 + 双写过渡期 + 回填校验；回滚只需撤 type_id 列 |
| 老接口调用方（其他页面/脚本）传 `dimension_type` | 后端兼容解析：`dimension_type` 参数自动转 `type_id`（按 code 匹配） |
| 类型删除误删 | FK `ON DELETE RESTRICT` + 服务层 409 双保险 |
| 树形层级（类型树/值树并存）语义混淆 | 文档明确：左侧=类型树（新），右侧=值列表（保留 parent_id 树形展示可选） |
| 与 multica 其他 issue 冲突 | 实施前 fetch 最新 dev，基于最新代码改 |
